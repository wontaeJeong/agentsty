# Production 요구사항

## 1. 목적과 현재 상태

AgentCask는 격리된 코딩 Agent 세션을 제공하는 정식 서비스를 목표로 개발한다. 이 문서는 목표 요구사항이며 구현 완료 선언이 아니다. 현재 구성과 사용법은 [아키텍처](ARCHITECTURE.md), [README](../README.md), 계약은 API/CRD/CLI 스펙이 설명한다. 초기 구현 단계의 성공이 이 문서 충족을 의미하지 않는다.

## 2. 모든 기능에 적용하는 필수 역량

| 영역 | 필수 요구사항 |
| --- | --- |
| 실제 사용자 경험 | 지원하는 사용자 시나리오를 실제 런타임·연동 환경에서 검증하고 실패·취소·재접속 동작을 정의한다. |
| 신원·권한 | 사용자와 세션별 인증·인가, 소유권/테넌트 경계, 권한 철회 및 위협 모델을 반영한다. 요청 본문의 신원을 신뢰하지 않는다. |
| Secret | upstream 키는 내부 `cask-model-proxy`만 보유한다. AgentSession, Agent Pod, API/CLI/터미널 출력, 로그에 노출하지 않는다. 세션 토큰은 수명·범위·철회를 통제한다. |
| 실행·데이터 격리 | 비신뢰 코드에 위협 모델에 맞는 격리를 적용한다. 사용자/세션 간 데이터·자원 접근을 차단하고 최소 RBAC와 기본 비공개 네트워크를 적용한다. |
| 다중 사용자·세션 | 동시 실행, 자원 경합, 한 사용자/세션의 장애가 다른 사용자/세션에 미치는 영향을 검증한다. |
| 장애·복구 | 의존성 장애, 재시작, 타임아웃, 부분 실패, 정리 실패에 대한 동작과 복구 절차를 정의한다. 보장하는 영속성 및 데이터 손실 범위를 명시한다. |
| 계약 | API/CRD/이벤트와 클라이언트 계약을 버전 관리한다. 호환성, 변경·중단 정책, 마이그레이션 및 롤백 경로를 검증한다. |
| 관측성 | 비밀을 제외한 로그·지표·감사 이벤트와 필요한 추적, 상태/오류 식별, 경보 및 대응 절차를 제공한다. |
| 운영 품질 | 목표 규모에 맞는 확장성과 유지보수성, 재현 가능한 구성/배포, 공식 문서/운영 가이드, 성능·자원 예산을 증거로 확인한다. |

인증/인가와 자원 통제는 필수이나 특정 OIDC 제품, 조직 관리 UI 또는 유료 Billing 기능 자체를 일괄 필수로 만들지는 않는다. 측정 목표와 출시 증거는 [Release Criteria](RELEASE_CRITERIA.md)에서 관리한다.

## 3. 요구사항에 따라 선택하는 제품 기능과 기술

아래 항목에 대한 초기 제외/축소 규칙은 더 이상 유효하지 않다. 각각 사용자 요구, 위험, 의존성, 비용을 근거로 우선순위를 정한다. 현재 구현 또는 출시 약속을 뜻하지 않는다.

- Web UI, 관리 포털, CLI 외 클라이언트.
- 조직·세분화 권한 관리, quota, billing/chargeback.
- OIDC/중앙 인증, Vault, SPIFFE, External Secrets 등 보안 통합.
- Terminal Gateway 독립 서비스화, provider/모델별 gateway 및 고급 모델 트래픽 정책.
- 영속 저장소, 워크스페이스 수명주기, 세션 영속화·복구·고급 관리.
- 이벤트 기반 controller, 동적 리소스·격리 정책.
- 복수 Agent Runtime 및 이미지/어댑터별 지원 계약.
- HA, 수평 확장, 멀티테넌시, 다중 클러스터 등 목표 운영 규모에 필요한 구성.

보안 필수 역량을 선택 기능 목록을 이유로 연기하지 않는다. 반대로 위험/요구가 없는 추상화나 복잡한 인프라를 미리 도입하지 않는다. 목표 SLO나 용량이 HA를 필요로 하면 해당 릴리스에서 선택이 아닌 충족 조건이 된다.

## 4. 구조 변경 원칙

Go 핵심 서비스와 Kubernetes AgentSession CRD를 기본 자산으로 유지하되 초기 배포 모양을 영구 고정하지 않는다. [설계 결정/ADR](DESIGN_DECISIONS.md)에 근거, 보안 경계, 운영 영향, 계약 호환성 및 복구/롤백 전략을 남긴다. 실제 upstream 자격 증명의 Agent Pod 노출 금지와 사용자 직접 Kubernetes/Pod 접근 금지는 구조와 무관하게 유지한다.

## 5. 추적

각 기능은 요구사항 → ADR(필요시) → 구현/테스트 → 운영 문서 → 출시 증거로 추적 가능해야 한다. [로드맵](PRODUCTION_ROADMAP.md)은 후속 작업 순서와 미검증 항목을 관리한다. Mock/Fake/Stub는 테스트 도구일 뿐 실제 서비스 기능 완료의 근거가 아니다.
